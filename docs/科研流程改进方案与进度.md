## 目标与约束

1. 写前形成“规划 → 检索 → 分析 → 有界补检 → 分析 → 写作”闭环。
2. 写后形成“审核 → 按问题补检/重新分析/局部修订 → 复审”闭环，禁止为可选假设无限找支持。
3. 本地与 Web 使用统一来源/证据对象；计划、章节、结论、原文位置具有可检查的关联。
4. 执行状态、审核结论、结束原因分开；失败或资料不足不能包装为质量通过。
5. 持久化成功后才能承诺可恢复或完成；取消、子任务失败、切换会话不能遗留写入或串流。
6. 优先兼容已有 API、历史检查点与知识库；不因迁移给旧任务重置或增加检索总预算。

角色边界：Planner 产出任务；Scout 执行检索并报告来源；Analysis 判断证据覆盖/冲突并组织章节证据；Writer 写作/修订；Reviewer 核验并批准修复动作；Visualizer 展示可信分析数据。执行器统一处理跳转、预算和状态提交。

## 验收结果与剩余风险

### 1. 本轮实际改了什么

#### 阶段 1：把两个闭环及职责边界落实到执行代码

- Planner 的任务/查询与章节关联进入检索器，不再仅存入计划供展示。
- Scout/ Retriever 负责获取与登记证据；Analysis 负责语义覆盖和假设判断。写作前先检查证据充分性；不足则补检并返回分析。
- 默认策略由 `review_only` 改为 `dual_loop`，写前分析补检最多 2 轮；审核服务重试最多 1 轮，同时受总预算约束。历史检查点迁移保留已消费预算。
- 区分“候选缺口”和“审核批准的修复任务”。Reviewer 可以否决候选；可选假设不足不自动成为无限补检理由。
- 证据矛盾进入重新分析；表述问题进入修订；服务故障进入有界重试或未确认终态，不把所有问题都从 Planner 重跑。
- Analysis 服务重试后仍不可用：不进入 Writer，保存 `analysis_unavailable`，标记未确认。仍有可读证据但预算用完的情况，只能给明确声明限制的部分结果。
- 并行写作只在所有章节成功后提交状态；一个章节失败会取消并等待其他章节，避免后台残余写入。

主要实现：`backend/app/service/deep_research_v2/science_roles.py`、`science_retrieval.py`、`state.py`、`backend/app/config/research_profiles.py`。

#### 阶段 2：把“可追溯”从字段扩展为受约束的证据链

- 本地和 Web 进入统一来源视图；文献数量与 chunk 数量分开。相同有效 DOI 可合并来源，但保留片段与版本；同题名不同显式 DOI 不合并。
- 本地检索保留知识库、文档、文档版本、chunk、资产及位置等身份；用服务端身份检查知识库/用户归属。
- 章节证据包使用语义关联及中英文相关性兜底，不把证据轮流分给章节。模型输入有总长度预算，截断会注明。
- 表格按需补齐表头、单位、目标行与邻接上下文；重复召回不会丢弃已取得的资产上下文。图片只有题注/位置时仍是“视觉内容未核验”。
- `claim.evidence_links` 关联原文片段或资产。资产身份、版本、locator、quote、text_span 均需校验；一行的引文不能冒充另一行的支持。
- 报告生成 `#claim-evidence:<claim_id>:<index>` 引用。前端按**当前展示报告自己的证据快照**解析，可打开版本化资产预览，不拿新报告的相同编号解释旧引用。
- 旧数据只有 chunk 定位时标记 `chunk_only`，没有精确行号就不制造行号。`validated` 只表示定位字段通过校验，**不表示结论已经事实核验通过**。
- 文献范围保留用户显式要求；移除通用研究默认排除 SAR 等示例约束。

主要实现：`evidence.py`、`literature_sources.py`、`backend/app/service/document_assets.py`、`retrieval_service.py`、`backend/app/router/knowledge_router.py`、`frontend/src/components/claim-evidence-boundary.tsx`。

新增资产上下文读取契约：

```text
GET /knowledge-bases/{kb}/documents/{doc}/assets/{asset}/evidence
    ?document_version=...&query=...&max_chars=5000
```

该接口依赖既有登录身份与归属检查；缺失/越权/版本不匹配不能回退到别人的资产。现有资产列表接口也支持可选 `document_version`。

#### 阶段 3：让长流程状态、失败与恢复可信

- 保存完整快照、状态、预算及下一阶段后，才推进或发完成事件。持久化失败发专门错误，不声称“已保存”；能恢复的只是先前成功写入的 checkpoint。
- 事件缓冲上限 256。只有明确可丢弃的进度事件可被丢弃；关键事件溢出会明确停止，不静默丢掉完成/错误等事件。
- 独立取消监视不依赖 SSE 消费者是否正在读取，轮询间隔 0.2 秒；取消后等待 Agent 退出再保存。已完成后断连不降级为暂停。
- 所有研究 JSON SSE 事件携带 `run_id/session_id`。当前兼容策略仍为 `run_id=session_id`，不是引入了新的多运行数据库模型。
- 同会话已有 checkpoint 时，新 `/stream` 返回 409 `research_run_exists`；查询已有任务失败返回 503，不冒险覆盖。新问题走“新建研究”，当前任务走恢复或追加复核。
- 前端增加复核说明、关联 claim、追加轮数与使用剩余预算选项；最终权限/预算由后端校验，表单不构成绕过渠道。
- 修复旧 SSE、旧 history/checkpoint 请求、旧 stop/finally 回调覆盖新会话的边界；停止后可以再次恢复。
- 执行 `completed` 与审核 `review_verdict/outcome` 分离。评分不等于审核通过；无效评分、未核验、预算耗尽均明确展示。失败步骤在完成与恢复事件后仍是失败。

主要实现：`graph.py`、`checkpoint_service.py`、`research_router.py`、`service.py`、`frontend/src/utils/research-stream.ts`、`frontend/src/pages/chat/index.tsx`、`shared.ts`。
