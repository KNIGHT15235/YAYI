## 1. 方案结论

**保留现有工程，在原链路上做三类改动：科研提示词与配置、文献和引用的结构化关联、证据不足时的补检调度。**

现有六角色、FastAPI、知识库上传、Embedding/Milvus、网页检索、报告与图表展示、SSE、PostgreSQL checkpoint、Redis 和记忆机制继续使用。先让已有流程稳定围绕科研问题运行，再补齐精细文献定位和逐条引用核验。

需要新建的主要是少量数据模型、辅助服务和评测脚本，不增加新的 Agent，不重建平台，也不要求重新配置用户现有虚拟环境。

## 4. 第二批：文献资产与原文位置关联

这部分需要增加数据结构。单纯修改 Prompt 无法可靠获得表格行、公式编号、页码或图表位置，应从解析结果中取得并保留下来。

### 4.1 保留 DocMind 结构化结果

修改 [docmind_service.py](D:/ldj/01/YAYI_0929/backend/app/service/docmind_service.py)：

1. 新增结构化结果归一函数，输出正文、版面块、表格/公式/图片资产及文本范围信息。
2. 保留现有 `collect_all_results()` 作为返回文本的兼容包装，避免影响附件与旧调用路径。
3. 页码、坐标、表格行、公式编号等只采用解析结果中真实存在的值；缺失则留空，不让模型猜测定位。
4. 根据实际解析输出保存图表资源；缺少可下载图像时，后续可按有效 PDF 坐标裁切，作为独立的小步骤接入。

### 4.2 增加带偏移量的分块信息

现有 `chunk_text()` 接口保留，新增返回文本起止范围和来源位置的版本。通过片段范围与版面块范围的重叠建立关联，减少大幅重写原分块算法。

分块时尽量保持表格、公式及其解释完整；超长结构必须拆分时，保留共同结构 ID 与上下文说明。重叠片段可以共享资产引用，避免每个片段复制一份图片。

### 4.3 PostgreSQL 增加两个小模型

在 [models/knowledge.py](D:/ldj/01/YAYI_0929/backend/app/models/knowledge.py) 中拟新增：

|模型|主要字段|作用|
|---|---|---|
|`DocumentAsset`|现有 Document UUID、资产 ID、类型、内容或文件路径、页码、坐标、表格/公式/图编号、内容哈希|管理独立资产及其原文位置|
|`DocumentChunkProvenance`|Document UUID、文档版本、集合名、Milvus chunk ID、chunk index、文本范围、关联资产|把已有向量命中结果连接到精细来源位置|

迁移采用新增表和可空字段，先服务新上传文档；旧文档仍能返回文本和原件下载，之后按选定文档补解析，不要求一次性全库重建。

**文档身份必须稳定：**现有向量 `doc_id` 使用文件名哈希，不能作为跨知识库的全局文档身份。新关联以 PostgreSQL Document UUID 为主，同时保留集合和片段 ID，覆盖同名文件与多知识库场景。

新上传文档的 chunk ID 使用 Document UUID、文档版本与 chunk index 生成稳定哈希，写入现有 VARCHAR 字段，避免同库同名文件的片段冲突；旧 chunk ID 继续兼容，不要求重建旧集合。

### 4.4 复用存储、下载和检索

- [knowledge_router.py](D:/ldj/01/YAYI_0929/backend/app/router/knowledge_router.py) 的 `process_document()` 传入真实 Document UUID，保存资产和片段映射；文档删除时清理对应记录与文件。
- [milvus_service.py](D:/ldj/01/YAYI_0929/backend/app/service/milvus_service.py) 保持现有向量字段、1024 维和索引；无须为资产元数据迁移整个集合。
- [retrieval_service.py](D:/ldj/01/YAYI_0929/backend/app/service/retrieval_service.py) 保留命中的 chunk ID、chunk index，再批量查询 PostgreSQL 补全定位，避免逐条数据库查询。
- Scout 继续传递 Document UUID、资产 ID 与 locator，不能在转为研究搜索结果时丢掉这些字段。
- 资产读取复用原件下载的用户归属检查；链接中不直接暴露磁盘路径。

**验收：**选择包含正文、公式、表格和图片的真实论文，逐项核对原页；同时覆盖同名文件、多知识库、旧文档、解析失败、删除清理与越权请求。

## 5. 第三批：引用与证据统一关联

### 5.1 新增轻量证据服务

拟新增：`backend/app/service/deep_research_v2/evidence.py`。

该服务负责标识归一、来源去重、引用绑定和基础校验，继续由现有六角色调用，不单独增加“引用 Agent”。

建议数据分为两层：

```text
Evidence：evidence_id、document_id/source_id、来源元数据、原文摘录、
          locator、content_hash、获取时间

Claim：claim_id、claim_text、evidence_ids、verification_status、reason
```

Evidence 表示原始证据，Claim 表示综述中需要证据支持的声明。记录可先随研究状态存入现有 JSONB；大正文和图片保持外部存储，状态中仅保留必要摘录与资源标识。

### 5.2 全链路传递证据 ID

Scout 的正常检索、递归检索和补检统一登记来源与证据；DataAnalyst 的数据点保留对应证据 ID；Writer 只能引用输入中存在的证据，服务端据此生成最终来源信息与链接。

重点修改 Writer 的 `_write_section()`、`_synthesize_report()`、`_revise_report()`。每次整合和修订后重新校验：引用 ID 是否存在、所属文档是否一致、正文是否仍使用旧来源。未知引用不能由模型自行补造 DOI 或 URL。

### 5.3 逐声明分批审核

Critic 复用现有审核和路由逻辑，新增按 Claim 分批核对证据的步骤，分别记录支持、矛盾、证据不足和未核验。

当前审核输入存在事实条数、数据点条数及报告长度截断。逐条审核需要显式覆盖全部声明，并记录 `checked/skipped`，不能仅审核前半部分后将全文标为通过。

可由程序确定的检查先完成，例如引用 ID 存在性、来源关联、数值单位与简单计算；语义支持关系交给模型审核。完成后汇总问题，再进入原五维评分及补检/修订分支。

**验收：**不存在的引用、引用错配、数字抄错、夸大结论、修订后遗留旧引用、长报告末尾错误均能被定位；“未核验”不得静默算成通过。

## 6. 第四批：分析阶段证据不足时复用补检分支

### 6.1 在 Analyst 增加证据覆盖判断

在 DataAnalyst 绘图之前增加 `_assess_evidence()`，返回：

```text
sufficient / missing_questions / required_evidence / suggested_queries
```

判断依据包括研究子问题覆盖、直接来源是否存在、关键实验条件是否完整，以及证据是否相互矛盾；不能只依靠单一置信分数。

### 6.2 小幅修改调度，不迁移编排框架

在 [state.py](D:/ldj/01/YAYI_0929/backend/app/service/deep_research_v2/state.py) 增加带默认值的状态字段：

- `evidence_assessment`：本轮证据覆盖结果。
- `supplementary_origin`：补检来自分析还是审核。
- `return_phase`：补检结束后返回的阶段。
- `analysis_search_round`：分析补检次数，独立于审核修订次数。

在 `graph.py` 的现有调度中加入明确跳转：

```text
分析证据充分：Analyst → Wizard → Writer → Critic
分析证据不足：Analyst → Scout 补检 → Analyst
审核证据不足：Critic → Scout 补检 → Writer 修订 → Critic
审核表达问题：Critic → Writer 修订 → Critic
```

**不能只修改 `state["phase"]`。**现有 `initial_steps` 在 Analyst 结束后仍会执行 Wizard 并推进 writing，需要一起修改阶段分支，才能真正阻止带着缺失证据继续写作。

复用 Scout `_supplementary_research()`，将“必定来自审核”的文案和固定写作返回阶段改为读取上下文。补检遵守本地/网络开关、查询数量及总轮数上限。

### 6.3 与 checkpoint、图表更新配合

新增字段沿用 JSONB 保存，旧 checkpoint 缺少字段时填入默认值。恢复时读取真实下一阶段和补检返回阶段；回到分析后按稳定 ID 更新数据点和图表，避免重复追加。

若达到补检预算仍缺乏证据，保留缺口并限制报告结论，不因预算耗尽自动将 `sufficient` 改为 true。

**验收：**覆盖四条分支、禁止联网时的补检、预算耗尽，以及补检前后中断恢复；Critic 原有审核回环与取消功能继续正常运行。

|`audit/score_science_eval.py`|从保存的输出与标注重算指标，输出分学科结果|

Recall@20 固定为文献级或明确约定的评测单位，统计前 20 个结果前先处理同文献多片段重复。引文事实错误率固定核验单位和分母，分别记录错误、无证据和未决情况，不通过排除失败样本提高指标。

每次结果记录语料版本、查询集、模型、Prompt/profile 版本、时间、成功与失败数以及人工复核记录。工程回归中的 mock 用于验证逻辑；召回和事实质量需要真实资料与对应标注，不以 mock 通过率替代。
