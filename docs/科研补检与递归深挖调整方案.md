# 科研补检与递归深挖调整方案（已实施）

项目：`D:\ldj\01\YAYI_0929`。

当前状态：用户确认后于 2026-09-30 实施。科研补检统一由 Review 决策，Scout 接入有界递归；网页新增科研背景调研与行业调研切换。具体测试结果见 `audit/科研补检与模式切换验证.md`。

## 设计理由

将补充检索的决策权集中到 Review，使 Analyze 专注证据整理、假设评估和缺口识别。Review 结合用户任务覆盖、报告实际声明和引用支持情况，统一判断哪些问题值得补检，哪些应缩小结论或明确保留为局限。这样可以统一补检门槛与预算，减少分析、审核各自回退搜索造成的重复检索和职责交叉。

这不意味着停止假设驱动研究，也不意味着停止评估材料是否充分。Analyze 仍产生假设判断、证据缺口和建议检索词，但不能自行进入补检阶段。是否更快取决于任务：若初始材料不足，先形成草稿再审核可能增加首轮撰写成本，因此不承诺每次任务都节省时间或 token。

## 已核对的兼容问题

以下是修改前的兼容问题，现已在实现中处理：

1. `science_roles.py` 的 Analyze 目前可以发起最多两轮补检。Review 依赖其旧 `evidence_assessment.sufficient`，单个声明缺证时不一定触发定向检索；报告遗漏的问题也可能没有声明可供审核。
2. Review 补检后，`graph.py` 已刷新图谱和统计图表，但跳过了假设、洞见和充分性重评。不能仅把返回阶段换成 Analyze，因为现有 Analyze 后固定进入初稿撰写，需要明确区分“首轮撰写”和“修订已有报告”。
3. 科研 Scout 当前绕过旧 `_execute_deep_search`。旧递归直接写模型提炼的 `facts/data_points`，不具备科研证据库所用的稳定证据 ID、来源核对和引用关联，不能直接当作论文证据接入。
4. 当前光学遥感变化检测检索器使用固定六组检索式。只读调用验证表明：原问题与追加跨场景反例关注词的问题，最终六组检索式完全相同。必须分离原始研究范围与实际扩展检索式，才能让补检和递归真正产生定向检索。
5. 原递归只有深度限制，没有会话总查询预算和持久化已访问查询集；不能把审核修订次数当成递归请求预算。
6. 当前无证据的 Analyze、无可读资料的 Writer 会在到达 Review 前失败。若需要统一由 Review 决定是否救援补检，必须补一个“无草稿的证据预检”分支。

## 实施方式

### 1. Review 是补检的唯一决策入口

- Analyze 保留来源数量、可读内容、任务覆盖与假设判断，输出结构化缺口，不直接搜索。
- Review 合并任务覆盖缺口和声明核验结果，区分需要补检、仅需修订、无法消除的局限。
- 每项补检任务记录触发原因、用户要求、关联章节/声明、所需证据及定向查询词。
- 不因候选假设未被证实而强制搜索到其成立；反例和“证据不足”均允许成为结论。
- 完全没有可读证据时，由 Review 执行证据预检，决定补检或结束；不让 Writer 凭空生成初稿，也不输出虚假的审核通过分数。

正常主链：

`规划 → Scout 初次检索 → Analyze → 图表 → 撰写 → Review`

Review 授权补检后的链路：

`Review → Scout 定向补检 → Analyze 重新评估 → 更新图谱/图表 → 修订已有报告 → Review`

### 2. Scout 内部采用有界递归

- 递归属于一次 Scout 检索批次内部的“原始来源追溯/线索扩展”，不赋予 Analyze 补检权限。
- 初次 Scout 检索和 Review 授权的补检批次中均可递归；初次检索内部的扩展与阶段间补检分别记录。
- 默认最大深度 2、每节点最多 2 条扩展查询、每项研究最多 8 条额外递归查询。整个研究最多 48 次实际 HTTP 尝试、扫描 2400 条记录、纳入 200 篇论文，累计检索时长 600 秒；单查询 90 秒、线索规划 45 秒。审核回合预算与递归预算分别计数。
- 查询去重、DOI/题名去重；无新增有效证据、超时或预算耗尽时结束相应分支。
- 支持对原有论文补足摘要/正文，不因题名重复而阻止证据升级。
- 锁定用户原始主题和年份；扩展词不能扩大任务范围。
- 模型只提出线索；文献和事实须由真实来源获取，经核对后进入统一 evidence ledger，再参与引用、图谱和图表。
- 将队列、父线索、深度、已访问查询及消耗预算写入检查点。暂停恢复继续未完成工作，不重置预算。

实施采用初次检索与 Review 授权补检均可递归。它是 Scout 内部的来源扩展，Analyze 不因此获得补检权限。通用主题通过原始查询和可识别主题词约束检索，最终语义相关性由 Review 审核，关键词过滤不等于完整语义核验。

## 修改范围

- `backend/app/config/research_profiles.py`：科研补检策略与递归预算。
- `backend/app/service/deep_research_v2/science_roles.py`：Analyze 缺口交接、Review 决策、Scout 科研递归及证据重评。
- `backend/app/service/deep_research_v2/literature_sources.py`：定向查询、来源追溯、原始范围约束和缓存键。
- `backend/app/service/deep_research_v2/state.py`、`evidence.py`：任务/递归状态、证据合并与旧检查点兼容。
- `backend/app/service/deep_research_v2/graph.py`：补检后重新分析、初稿/修订分流及恢复路径。
- 对应测试与实施说明。

保留六个 Agent 和各自模型，DataAnalyst 仍为 qwen-plus。登录界面和图标保持原样。已完成研究的历史正文不迁移、不重新生成。旧未完成检查点恢复时兼容旧字段，应用新的补检策略；保留已用审核回合。旧版本没有记录的 HTTP/扫描量按既有回合保守估算，并显式标明估算来源，不伪装成真实计量。

## 网页模式切换

“深度研究”页新增“科研背景调研 / 行业调研”选项。默认科研；切换后同步改变示例、提示和工作流说明。行业模式可选择行业主题，也可直接输入其他行业的问题。

选择值经新会话传递到 `/research/stream` 的 `profile_id`，行业模式不发送科研最少文献数。研究进行中及历史恢复使用会话已保存的模式，不受新建页面的选择影响；继续研究不会覆盖检查点配置。没有选择检索范围时会提示，避免静默退回普通对话。

## 验收重点

1. Analyze 发现不足时不进入补检，仍保留假设和缺口。
2. Review 能按任务缺口及具体声明授权定向补检，也能正确选择缩小结论。
3. 新增证据后重新评估，充分性可以由不足变为充分，假设/图谱/图表/引用同步更新。
4. 补检进入修订已有 claims，避免无意重写整个初稿。
5. 无草稿且无可读资料时，Review 预检与停止行为正确。
6. 扩展查询确实进入检索器；范围约束、去重、证据升级和无增益终止有效。
7. 深度、总查询与审核预算分别生效；暂停恢复不重复计费或赠送预算。
8. 行业原路径与科研前端展示回归通过。

行业真实联调中还修复了模型来源字段返回数组时的类型兼容问题，并在执行异常时保存当前阶段的中间状态，支持通过既有恢复接口继续研究。行业报告修订不再截取原稿前 6000 字，且加入章节保全检查，避免后半部分被截断的输出覆盖完整报告。这些修复保留原有研究决策。

实现与验证已按本方案执行。自动化回归使用受控模型/HTTP数据检验状态与预算；真实服务运行记录单独保存，不把离线测试视为研究质量指标。
