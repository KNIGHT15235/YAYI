## 修改文件与接口

- `backend/app/service/memory_service.py`：统一 Token 计数、PG 事务 advisory lock、按消息 ID/字符偏移去重、单批摘要缓存、真实失败信号、向量 upsert、关键词/向量融合、偏好上下文。
- 新增 `backend/app/service/memory_jobs.py`：只登记新消息的摘要队列、索引队列、归属复核、批次进度、互斥锁、有界重试、会话删除清理。
- `backend/app/router/session_router.py`：消息成功提交 PG 后登记；删除会话后立即清除该用户会话的摘要队列。
- `backend/app/service/scheduler_service.py`：注册 `new_message_memory_compression`；在工作线程执行同步任务。
- `backend/app/router/memory_router.py`：手动保存/搜索保持原请求结构；响应新增可选 `indexing_status` 和 `warning`；阻塞模型任务使用同步路由在线程池运行。
- `backend/app/router/chat_router.py`：三个 completion 入口验证有 ID 的会话归属，向模型传用户 ID，附件正文只读取当前用户附件；显式 `kb_name` 调用主任务新增的 `resolve_owned_knowledge_base`。无私库选择时保留既有通用检索，不枚举其他用户知识库。
- `backend/app/schemas/chat.py`：聊天请求新增可选 `kb_name`。
- `backend/app/service/chat_service.py`：增加 `MEMORY_CONTEXT_ENABLED` 开关。

已登录聊天通过原有前端消息保存请求登记自动记忆。只调用 completion 而不保存 PostgreSQL 消息的第三方客户端不会自动登记；手动接口仍可处理该用户明确选择的已保存会话。携带会话 ID 的 completion 现在要求登录并验证 PG 会话归属；无会话 ID 的匿名问答仍可使用，但不读取私人记忆、附件或知识库。

## 配置和调度验收

| 环境变量 | 默认值 | 含义 |
|---|---|---|
| `MEMORY_AUTO_ENABLED` | `true` | 是否登记/处理自动摘要；关闭不会遍历历史补录 |
| `MEMORY_CONTEXT_ENABLED` | `true` | 是否在普通聊天中检索并注入相关记忆 |
| `MEMORY_VECTOR_ENABLED` | `true` | 是否构建、检索向量；关闭仍可保存摘要并关键词搜索 |
| `MEMORY_TOKEN_THRESHOLD` | `10000` | 当前队列中尚未完成消息的本地估算 Token 阈值，至少 1 |
| `MEMORY_INTERVAL_MINUTES` | `30` | 周期检查间隔，至少 1 分钟 |
| `MEMORY_MAX_RETRIES` | `3` | 一个已登记任务允许的自动尝试次数，包含首次，至少 1 |
| `MEMORY_JOBS_PER_RUN` | `5` | 每周期最多处理 5 个会话摘要任务、5 个索引任务，分别上限 20 |
| `MEMORY_MODEL` | `qwen-plus` | 摘要模型，沿用现有 DashScope key/base URL |

Token 使用已安装 `tiktoken` 的 `cl100k_base` 编码，与现有会话计数编码保持一致；它是统一的本地估算，**不等于 Qwen 的实际计费 Token 数**。

调度 jobs 应同时包含原 `daily_news_collection` 和新增：

```json
{
  "id": "new_message_memory_compression",
  "name": "新增对话记忆压缩与索引重试",
  "trigger": "interval[0:30:00]"
}
```

`next_run_time` 取实际启动时间；单进程调度使用 `max_instances=1`、`coalesce=True`。关闭自动压缩时不会处理摘要队列，但手动保存产生的索引任务仍可被调度处理。失败任务设置 60 秒、120 秒等退避到期时间，实际执行受周期调度约束，默认在后续 30 分钟检查时执行；不是精确到秒的重试定时器。

## 数据保护、去重与边界

1. 新队列命名空间是 `memory:v1`。只由新增消息保存入口登记明确的用户 ID、会话 ID、消息 ID；不从全部 ChatSession/ChatMessage 中回填。初始化、重启均不自动调用模型处理历史数据。
2. 摘要生成前同时使用 Redis 工作锁和 PostgreSQL 事务 advisory lock。PG 中的 `_source_message_ids` 表示已经完整摘要的消息，`_source_message_offsets` 记录超长消息已摘要到的字符位置。手动保存与自动处理共用去重逻辑。
3. 每次最多读取队列前 200 条消息，摘要输入正文含角色标记不超过 30000 字符。超过预算按字符偏移继续分批，**不会把未输入模型的尾部标记为已完成**。自动队列仅移除已完整处理的 ID；手动单次处理一个批次，有剩余内容时返回 warning，可再次保存继续。原 PG 消息保持完整。
4. 已成功摘要在提交 PG 前按用户/会话/消息范围缓存 24 小时，减少 DB 提交失败后的重复调用。索引任务独立于摘要任务，失败重试不会重复生成摘要；向量主键固定并使用 upsert。
5. 摘要失败保留待办 ID，达到次数上限从到期队列移除并标记失败，避免无限付费重试。新消息登记或用户手动保存可再次触发尝试。SDK 摘要请求设置 45 秒超时、关闭隐式 SDK 重试。传输结果不确定、进程在响应缓存前崩溃等情况下，不能保证供应商计费恰好一次。
6. Redis 不可用时保留已经提交的聊天消息，记录队列不可用警告；该条未成功登记的消息不做自动历史回扫，用户仍可手动保存。PG 已保存但索引登记失败时，摘要仍可关键词召回，手动保存可再次登记索引。
7. 删除会话立即清除该会话待办；清理当时 Redis 不可用时，worker 会先核对 PG 会话是否仍存在，不存在则清除待办并退出，不调用模型。用户/会话在某个外部请求已经发出后被并发删除，不能撤回已经发出的请求。
8. 关键词搜索按当前用户参数化过滤，英语大小写不敏感；中文使用短语和相邻双字片段。最多查询 100 条关键词候选；向量结果重新通过当前用户 PG 记录复核，删除/其他用户的向量不会重新进入结果。结果 `score` 是归一化的融合排序分，不是概率或准确率。
9. 摘要成功不代表向量完成。响应提供 `pending/completed/failed/disabled` 状态与说明。embedding 配额或服务故障时保留 PG 关键词召回，不报告虚构的向量成功。本轮没有调整模型服务额度。
10. 无数据库迁移，无用户画像训练或微调。偏好来自摘要 JSON，并仅作为相关历史参考加入上下文。
